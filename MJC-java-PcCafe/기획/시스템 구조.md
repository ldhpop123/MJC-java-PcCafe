# 시스템 구조

```
                 BaseFrame (abstract, extends JFrame)
                 ├─ 공통 레이아웃 / 폰트 / 창 크기
                 └─ initUI() 추상 메서드
                        ▲                    ▲
                        │ 상속               │ 상속
                  AdminFrame             GuestFrame  ×N (new 로 계속 생성)
                  - guests 목록 관리      - 로그인 / 회원가입
                  - 좌석판 표시           - 좌석 선택
                  - "게스트 추가" 버튼 ──▶ - TimerThread 1개씩 보유
                        │   ▲                    │
                        │   └── 채팅 / 시간 갱신 콜백 ┘
                        ▼
                    DAO 계층 ──▶ MySQL
```

- **상속**: `BaseFrame`을 `AdminFrame`, `GuestFrame`이 상속한다. (`LoginDialog` 등도 공통 부모를 두면 좋음)
- **게스트 창 생성**: "게스트 추가" 버튼을 누를 때마다 `new GuestFrame(this)` 실행 → 인스턴스 다중 생성
	- 상속은 클래스 정의에서 한 번, 창 여러 개는 **인스턴스 생성**
- **창 닫기 설정**
	- `AdminFrame`: `EXIT_ON_CLOSE` (프로그램 전체 종료)
	- `GuestFrame`: `DISPOSE_ON_CLOSE` (자기 창만 닫힘)
- 관리자는 `List<GuestFrame>`으로 모든 게스트 창을 알고, 게스트는 생성자로 받은 `AdminFrame` 참조를 가진다.

## 코드 예시

```java
public abstract class BaseFrame extends JFrame {
    protected BaseFrame(String title, int width, int height) {
        super(title);
        setSize(width, height);
        setLocationRelativeTo(null);
    }

    // 객체를 다 만든 뒤 화면 구성
    public final void display() {
        initUI();
        setVisible(true);
    }

    protected abstract void initUI();
}

public class AdminFrame extends BaseFrame {
    private final List<GuestFrame> guests = new ArrayList<>();

    @Override protected void initUI() {
        JButton addGuest = new JButton("게스트 추가");
        addGuest.addActionListener(e -> {
            GuestFrame g = new GuestFrame(this);
            guests.add(g);
            g.display();
        });
    }
    public void removeGuest(GuestFrame g) { guests.remove(g); }
}
```

> [!warning] 생성자에서 `initUI()`를 부르면 안 되는 이유
> 부모 생성자가 먼저 실행되므로, 그 안에서 `initUI()`를 부르면 자식 클래스의 필드(`guests` 등)가 아직 `null`이다. 그래서 `display()`에서 따로 부른다.
