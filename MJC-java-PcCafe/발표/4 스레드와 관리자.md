# 4. 스레드, 관리자 기능, 채팅

**한 줄 요약**: 손님마다 타이머 스레드가 하나씩 돌면서 1초마다 시간을 줄인다. 관리자는 좌석판에서 그 시간을 보고, 늘리거나 줄이거나 끝낼 수 있고, 손님과 채팅도 한다.

**맡은 파일**
- `src/main/java/pccafe/thread/TimerThread.java`
- `src/main/java/pccafe/ui/GuestFrame.java` (남은 시간 메서드, `onTick`, `forceLogout`, 채팅)
- `src/main/java/pccafe/ui/AdminFrame.java` (좌석판, 시간 ±, 강제 종료, 채팅)

---

## 4-1. 스레드가 뭐고 왜 필요한가

> 비유: 스레드는 "일꾼"이다. 프로그램에는 기본으로 **화면 담당 일꾼(EDT)** 이 한 명 있어서 버튼 클릭, 화면 그리기를 처리한다.

만약 화면 담당 일꾼에게 "1초 기다렸다가 시간 줄이기"를 계속 시키면, 기다리는 동안 버튼도 안 눌리고 화면도 멈춘다. 그래서 **손님마다 시간 담당 일꾼(TimerThread)을 따로 한 명씩** 둔다.

```
 화면 일꾼 (EDT, 1명)         시간 일꾼 (TimerThread, 손님 수만큼)
 - 버튼 클릭 처리               - 1초 자고
 - 화면 그리기                  - 시간 1 줄이고
                               - 화면 일꾼에게 "화면 바꿔줘" 부탁
                               - 60초마다 DB 저장
```

## 4-2. TimerThread

```java
public void run() {
    int tick = 0;
    try {
        while (!isInterrupted() && guest.getRemainSeconds() > 0) {
            Thread.sleep(1000);                     // 1초 자기
            int remain = guest.decreaseOneSecond(); // 1초 줄이기
            guest.onTick(remain);                   // 화면 갱신 부탁
            if (++tick % 60 == 0) {
                guest.saveRemainTime();             // 1분마다 DB 저장
            }
        }
        if (!isInterrupted()) {
            // 시간이 0이 돼서 끝난 경우 → 자동 로그아웃
            SwingUtilities.invokeLater(() -> guest.forceLogout("남은 시간이 모두 소진되었습니다."));
        }
    } catch (InterruptedException e) {
        // 사용 종료로 interrupt() 됨 → 그냥 끝
    }
}
```

| 포인트 | 설명 |
| --- | --- |
| 멈추는 법 | 게스트가 종료하면 `timer.interrupt()` → 자고 있던 `sleep`이 `InterruptedException`을 던지며 깨어남 → 반복문 탈출 |
| `setDaemon(true)` | 관리자 창을 닫아 프로그램이 끝날 때 타이머도 같이 끝나게 함 |
| 1분 자동 저장 | 프로그램이 갑자기 꺼져도 시간이 최대 1분만 손해 |

## 4-3. 규칙 1: 화면은 화면 일꾼만 바꾼다 (invokeLater)

Swing은 **화면 일꾼(EDT)만 화면을 바꿔야 한다**는 규칙이 있다. 다른 일꾼이 직접 라벨 글자를 바꾸면 가끔 화면이 깨지거나 이상하게 동작한다.

```java
// GuestFrame.onTick: 타이머 일꾼이 부름
public void onTick(int remain) {
    SwingUtilities.invokeLater(() -> {     // "화면 일꾼아, 이거 해줘"
        refreshDisplay();                  // 게스트 화면 + 관리자 좌석판 갱신
        if (remain == 300 && !warned) {    // 5분 남으면 경고
            warned = true;
            showInfo("남은 시간이 5분입니다.");
        }
    });
}
```

## 4-4. 규칙 2: 같은 값을 둘이 동시에 바꾸지 않는다 (synchronized)

남은 시간(`remainSeconds`)은 **두 일꾼이 같이 건드린다**.
- 타이머 일꾼: 1초마다 −1
- 화면 일꾼: 관리자가 "+10분" 누르면 +600

동시에 바꾸면 한쪽 변경이 사라질 수 있다.

> 예: 남은 시간 100. 타이머가 100을 읽음 → 관리자가 100을 읽고 700으로 저장 → 타이머가 99로 저장. **관리자가 준 10분이 사라짐.**

그래서 시간을 읽고 바꾸는 메서드에 `synchronized`를 붙였다. 한 번에 한 일꾼만 들어갈 수 있는 **열쇠 하나짜리 방**이라고 생각하면 된다.

```java
public synchronized int decreaseOneSecond() {
    if (remainSeconds > 0) remainSeconds--;
    return remainSeconds;
}

public void addSeconds(int seconds) {
    synchronized (this) {
        remainSeconds = Math.max(0, remainSeconds + seconds);  // 0 밑으로는 안 내려감
    }
    refreshDisplay();
}
```

`member`, `seatNo`에는 `volatile`을 붙였다. 한 일꾼이 바꾼 값을 다른 일꾼이 **바로 보게** 하는 표시다.

## 4-5. 관리자 기능

### 좌석판
- 좌석 12개를 4칸 격자(`GridLayout`)로 보여준다.
- 빈자리 = 회색, 사용 중 = 파란색 + 이름 + 남은 시간
- 좌석을 클릭하면 파란 테두리가 생기고 "선택된 좌석: 3번"이 된다.
- 게스트가 1초마다 `admin.updateSeat(...)`를 불러서 좌석판 시간도 같이 줄어든다.

### 버튼

| 버튼 | 하는 일 |
| --- | --- |
| 시간 +10분 | 선택된 좌석 게스트의 `addSeconds(600)` |
| 시간 −10분 | `addSeconds(-600)` (0 밑으로는 안 내려감 → 0이 되면 타이머가 자동 종료) |
| 강제 종료 | `forceLogout("관리자가 사용을 종료했습니다.")` → 시간 저장 후 로그인 화면으로 |

```java
plus.addActionListener(e -> withSelectedGuest(g -> g.addSeconds(600)));
```

`withSelectedGuest`는 "선택한 좌석의 게스트 창을 찾아서, 있으면 이 일을 해라. 없으면 '사용 중인 좌석을 선택하세요'"라는 공통 메서드다. 버튼 3개가 같은 확인 코드를 반복하지 않으려고 만들었다.

## 4-6. 채팅

한 프로그램 안이라서 **서로의 메서드를 직접 부르면** 메시지가 전달된다. 소켓이 필요 없다.

```
 게스트 ──admin.receiveMessage(3, "홍길동", "안녕하세요")──▶ 관리자 채팅창
                                                            "[3번 홍길동] 안녕하세요"

 관리자 ──guest.receiveMessage("네 말씀하세요")──▶ 게스트 채팅창
          (선택된 좌석 번호로 guests 목록에서 찾음)      "관리자: 네 말씀하세요"
```

- 게스트는 생성자로 받은 `admin`을 알고 있다.
- 관리자는 `guests` 목록에서 좌석 번호로 게스트를 찾는다 (`findGuestBySeat`).
- 채팅 내용은 DB에 저장하지 않는다.

## 시연 담당
1. 좌석판에서 시간이 1초씩 줄어드는 것 보여주기
2. 좌석 클릭 → +10분 → **게스트 화면과 좌석판이 동시에** 바뀌는 것
3. 채팅 주고받기 (좌석 선택 후 입력 → Enter)
4. 강제 종료 → 게스트 창이 로그인 화면으로 돌아가는 것

> [!tip] 자동 종료를 보여주고 싶으면
> 남은 시간이 짧은 계정을 만들어 두거나, 관리자가 −10분을 여러 번 눌러 0으로 만들면 바로 "남은 시간이 모두 소진되었습니다"가 뜬다.

## 예상 질문
- **Q. 손님이 100명이면 스레드도 100개인가요?** → 그렇다. 과제 규모에서는 문제없다. 실제 서비스라면 스레드 하나가 모든 손님 시간을 줄이는 방식(`ScheduledExecutorService`)이 더 효율적이다.
- **Q. javax.swing.Timer를 쓰면 안 되나요?** → 쓸 수 있다. 그건 화면 일꾼에서 돌아서 `invokeLater`가 필요 없다. 과제가 "스레드 구현"이라 `Thread`를 직접 상속해서 만들었다.
- **Q. synchronized 없으면 정말 문제가 생기나요?** → 매번은 아니지만 가끔, 재현하기 어렵게 생긴다. 그래서 미리 막아두는 것이다.
