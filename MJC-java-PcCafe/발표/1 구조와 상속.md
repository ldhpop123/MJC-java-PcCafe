# 1. 전체 구조와 상속

**한 줄 요약**: `BaseFrame`이라는 부모 창을 하나 만들고, 관리자 로그인 창, 관리자 창, 게스트 창이 이걸 상속받는다. 게스트 창은 버튼을 누를 때마다 새로 만든다.

**맡은 파일**
- `src/main/java/pccafe/Main.java`
- `src/main/java/pccafe/ui/BaseFrame.java`
- `src/main/java/pccafe/ui/AdminLoginFrame.java`
- `src/main/java/pccafe/ui/panel/BasePanel.java` (상속 구조 설명만, 탭 내용은 [[2 DB와 DAO]])
- `src/main/java/pccafe/ui/AdminFrame.java` (게스트 추가 버튼 부분)
- `src/main/java/pccafe/ui/GuestFrame.java` (생성자, 창 닫기 부분)

---

## 1-1. 프로그램 모양

프로그램 하나(JVM 하나) 안에 창이 여러 개 뜬다.

```
         ┌──────────────┐
         │  관리자 창    │  ← 1개
         │ [게스트 추가] │
         └──────┬───────┘
                │ 버튼 누를 때마다 new
     ┌──────────┼──────────┐
     ▼          ▼          ▼
 ┌────────┐ ┌────────┐ ┌────────┐
 │게스트 1│ │게스트 2│ │게스트 3│  ← 원하는 만큼
 └────────┘ └────────┘ └────────┘
```

> 비유: 실제 PC방에서 카운터 컴퓨터 1대(관리자)와 손님 자리 컴퓨터 여러 대(게스트)가 있는 것을, 한 컴퓨터 화면 안에 창으로 흉내낸 것이다.

## 1-2. 상속 구조

```
                 JFrame  (자바가 제공하는 창)
                   ▲
                   │ extends
               BaseFrame  (우리가 만든 공통 부모, abstract)
        ▲          ▲           ▲
        │          │           │ extends
 AdminLoginFrame  AdminFrame  GuestFrame
```

관리자 창 안의 탭들도 같은 방식으로 상속을 쓴다.

```
                 JPanel
                   ▲
               BasePanel  (abstract, refresh()를 자식이 구현)
     ▲          ▲          ▲          ▲
 MenuPanel  OrderPanel  MemberPanel  SalesPanel
```

**왜 부모를 따로 만들었나?**
창들 모두 "제목 정하기, 크기 정하기, 화면 가운데 띄우기, 오류 메시지 띄우기"가 똑같이 필요하다. 이걸 두 번 쓰지 않고 부모에 한 번만 써 두었다.

```java
public abstract class BaseFrame extends JFrame {
    protected BaseFrame(String title, int width, int height) {
        super(title);
        setSize(width, height);
        setLocationRelativeTo(null);   // 화면 가운데
    }

    public final void display() {
        if (!initialized) {
            initUI();                   // 자식이 만든 화면 구성
            initialized = true;
        }
        setVisible(true);
    }

    protected abstract void initUI();   // 자식이 꼭 만들어야 하는 메서드

    protected void showInfo(String message) { ... }   // 공통 알림창
    protected void showError(Exception e) { ... }     // 공통 오류창
}
```

- `abstract class`: 그 자체로는 창을 만들 수 없고, 상속받아서만 쓸 수 있다.
- `abstract void initUI()`: "화면 구성은 자식이 알아서 해라"라는 약속. 관리자 창과 게스트 창은 생김새가 다르니까.
- 자식은 `super("PC방 관리자", 1000, 650)`처럼 제목과 크기만 넘기면 된다.

> [!question] 예상 질문: initUI()를 왜 생성자에서 안 부르고 display()에서 부르나요?
> 자바는 자식 객체를 만들 때 **부모 생성자를 먼저 실행**한다. 그때는 자식 클래스의 필드(예: `guests` 리스트)가 아직 만들어지지 않아서 `null`이다. 부모 생성자 안에서 `initUI()`를 부르면 `null`인 필드를 건드려서 오류가 날 수 있다. 그래서 객체가 다 만들어진 뒤에 `display()`에서 부른다.

## 1-3. 상속 vs 인스턴스 (헷갈리기 쉬운 부분)

| 구분 | 의미 | 코드 | 몇 번? |
| --- | --- | --- | --- |
| 상속 | 설계도를 물려받음 | `class GuestFrame extends BaseFrame` | 클래스 만들 때 1번 |
| 인스턴스 생성 | 설계도로 실제 창을 찍어냄 | `new GuestFrame(this)` | 버튼 누를 때마다 |

> 비유: 상속은 "붕어빵 틀을 만드는 것", 인스턴스 생성은 "그 틀로 붕어빵을 굽는 것". 게스트 추가 버튼은 붕어빵을 하나 더 굽는 버튼이다.

```java
// AdminFrame.java
private void openGuest() {
    GuestFrame guest = new GuestFrame(this);   // 새 게스트 창 만들기, 관리자 자신(this)을 넘김
    guests.add(guest);                         // 관리자가 목록으로 기억
    guest.setLocation(getX() + 40 * guests.size(), getY() + 40 * guests.size());  // 겹치지 않게 비켜서
    guest.display();
}
```

- 관리자는 `guests` 리스트로 **모든 게스트 창을 기억**한다.
- 게스트는 생성자로 받은 `admin`으로 **관리자 창을 기억**한다.
- 이렇게 서로를 알고 있어서 시간 갱신과 채팅이 가능하다. (자세한 건 [[4 스레드와 관리자]])

## 1-4. 창 닫기 설정

| 창 | 설정 | X를 누르면 |
| --- | --- | --- |
| 관리자 | `EXIT_ON_CLOSE` | 프로그램 전체 종료 |
| 게스트 | `DISPOSE_ON_CLOSE` | 그 게스트 창만 닫힘 |

게스트 창에 `EXIT_ON_CLOSE`를 쓰면 손님 창 하나 닫았는데 관리자 창까지 다 꺼진다.

```java
// GuestFrame 생성자
setDefaultCloseOperation(DISPOSE_ON_CLOSE);
addWindowListener(new WindowAdapter() {
    @Override
    public void windowClosed(WindowEvent e) {
        endSession();                       // 남은 시간 저장, 좌석 비우기
        admin.removeGuest(GuestFrame.this); // 관리자 목록에서 빠지기
    }
});
```

## 1-5. 프로그램 시작과 관리자 로그인

```java
public static void main(String[] args) {
    SwingUtilities.invokeLater(() -> new AdminLoginFrame().display());
}
```

Swing 화면은 **화면 전용 스레드(EDT)** 에서 만들어야 안전하다. `invokeLater`는 "이 일을 화면 스레드에게 맡겨줘"라는 뜻이다. (스레드 이야기는 [[4 스레드와 관리자]]에서 더 나온다)

```
 실행 → [관리자 로그인 창] ──admin/admin──▶ dispose() ──▶ new AdminFrame(관리자).display()
                │
                └─ 일반 회원(test)이면 "관리자 계정이 아닙니다."
```

```java
// AdminLoginFrame.login()
Member m = memberDAO.login(id, pw);
if (m == null)       → "아이디 또는 비밀번호가 틀렸습니다."
if (!m.isAdmin())    → "관리자 계정이 아닙니다."
dispose();                       // 로그인 창 닫기
new AdminFrame(m).display();     // 관리자 창 열기 (제목에 관리자 이름)
```

- 관리자와 손님을 같은 `member` 테이블에 두고 `is_admin`으로 구분한다.
- 반대로 게스트 창에서 관리자 계정으로 로그인하면 막는다 → [[3 게스트 화면]]
- 로그인 창도 `BaseFrame`을 상속했다. 제목, 크기, 가운데 정렬, 알림창 코드를 또 쓸 필요가 없다. **상속의 장점을 보여주는 예시.**

## 발표 포인트
- 상속을 쓴 이유: **공통 코드를 한 곳에 모으려고**
- `abstract`를 쓴 이유: **자식마다 화면이 다르니까 화면 구성은 자식에게 맡기려고**
- 게스트 창 여러 개 = 상속이 아니라 **인스턴스를 여러 개 만든 것**

## 예상 질문
- **Q. 왜 소켓(네트워크)을 안 썼나요?** → 한 프로그램 안에 창이 다 있어서, 서로의 객체를 직접 알고 메서드를 호출하면 된다. 소켓은 컴퓨터가 여러 대일 때 필요하다.
- **Q. SignUpDialog는 왜 BaseFrame을 상속 안 했나요?** → 회원가입 창은 JFrame이 아니라 JDialog(팝업 창)라서. BaseFrame은 JFrame을 상속하기 때문에 JDialog의 부모가 될 수 없다.
