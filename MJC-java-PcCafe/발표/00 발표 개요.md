# 발표 개요

4명이 순서대로 발표한다. 앞사람이 만든 것을 뒷사람이 이어서 쓰는 순서라서, 이 순서대로 하면 듣는 사람이 따라오기 쉽다.

| 순서 | 담당 | 주제 | 핵심 한 줄 | 노트 |
| --- | --- | --- | --- | --- |
| 1 | 담당 1 | 전체 구조와 상속, 관리자 로그인 | 부모 창 하나를 상속해서 로그인 창, 관리자 창, 게스트 창을 만든다 | [[1 구조와 상속]] |
| 2 | 담당 2 | DB와 DAO, 관리 탭(CRUD) | 모든 데이터는 MySQL에 저장하고, SQL은 DAO에만 둔다 | [[2 DB와 DAO]] |
| 3 | 담당 3 | 게스트 화면, 음식 주문 | 로그인 → 좌석 선택 → 사용 → 종료할 때 남은 시간 저장 | [[3 게스트 화면]] |
| 4 | 담당 4 | 스레드, 관리자 기능, 채팅 | 손님마다 타이머 스레드가 하나씩 돌고, 관리자가 그걸 조종한다 | [[4 스레드와 관리자]] |

## 발표 흐름

```
[1] 프로그램이 어떻게 생겼나 (창 구조, 상속)
      ↓
[2] 데이터는 어디에 어떻게 저장하나 (DB, DAO)
      ↓
[3] 손님은 무엇을 하나 (로그인, 시간 구매, 종료)
      ↓
[4] 시간은 어떻게 흐르고, 관리자는 무엇을 하나 (스레드, 관리, 채팅)
      ↓
    시연
```

## 시연 시나리오 (마지막에 다 같이)

1. 프로그램 실행 → 관리자 로그인 창. `test`로 로그인하면 거절, `admin` / `admin`으로 로그인 (담당 1)
2. "게스트 추가"를 두 번 눌러 게스트 창 2개를 띄운다 (담당 1)
3. 게스트 창 1: 회원가입 → 로그인, 좌석 3번 선택 (담당 3)
4. 관리자 좌석판에서 3번이 파란색이 되고 시간이 1초씩 줄어드는 것을 보여준다 (담당 4)
5. 게스트 창 1: 시간 구매 30분 → 시간이 늘어난다 (담당 3)
6. 게스트 창 1: 음식 주문 라면 2개 → 관리자 채팅창에 `[주문]` 알림 + 소리 (담당 3)
7. 관리자 "주문" 탭: 방금 주문이 "대기"로 보임 → 완료 처리 (담당 2)
8. 관리자 "메뉴 관리" 탭: 라면 재고가 2개 줄어든 것 확인, 새 메뉴 추가 (담당 2)
9. 관리자 "매출" 탭: 시간 500원 + 음식 6,000원 확인 (담당 2)
10. 관리자: 3번 클릭 → "시간 +10분" → 게스트 화면 시간도 같이 바뀐다 (담당 4)
11. 게스트 ↔ 관리자 채팅 (담당 4)
12. 관리자: "강제 종료" → 게스트 창이 로그인 화면으로 돌아간다 (담당 4)
13. 관리자 "회원 관리" 탭: 남은 시간이 저장된 것 확인, 이름 검색 (담당 2)
14. 게스트 창 2: `test` / `1234`로 로그인 → 창을 X로 닫는다 → 회원 관리 탭(또는 TablePlus)에서 시간 저장 확인 (담당 3)

> [!tip] 시연 전에 준비할 것
> - MySQL 켜져 있는지 확인
> - `mysql -u root < sql/schema.sql`로 DB를 처음 상태로 초기화
> - TablePlus에서 `pccafe` 연결 열어두기

## 아직 안 만든 부분 (질문 나오면 솔직하게)

- 비밀번호 암호화 (지금은 평문 저장)
- 초기 계정(`admin` / `admin`)이 `schema.sql`에 그대로 있음
- 좌석판에 회원 이름을 HTML로 넣어서, 이름에 `<` 같은 문자가 있으면 표시가 깨짐
