# 3. 게스트 화면

**한 줄 요약**: 손님은 회원가입 → 로그인하면서 좌석 선택 → 시간 사용 / 구매 → 종료한다. 종료하거나 창을 닫으면 남은 시간이 DB에 저장된다.

**맡은 파일**
- `src/main/java/pccafe/ui/GuestFrame.java` (로그인, 시간 구매, 사용 종료)
- `src/main/java/pccafe/ui/SignUpDialog.java`

---

## 3-1. 손님의 하루

```
 [회원가입] ──▶ DB에 회원 저장
     │
     ▼
 [로그인 + 좌석 선택]
     │  아이디/비번 맞나? 이미 접속 중인가? 좌석 비었나?
     ▼
 [사용 중 화면] ── 남은 시간이 1초씩 줄어듦
     │   ├─ 시간 구매 → 시간 늘어남 + 결제 내역 저장
     │   ├─ 음식 주문 → 재고 차감 + 주문 저장 + 관리자에게 알림
     │   └─ 관리자와 채팅
     ▼
 [사용 종료] 또는 [창 X] 또는 [시간 0] 또는 [관리자 강제 종료]
     │
     ▼
 남은 시간 DB 저장 → 좌석 비우기 → 로그인 화면으로
```

## 3-2. 화면 두 장 바꿔 끼우기 (CardLayout)

게스트 창 하나 안에 화면이 2장 있다.

| 카드 | 내용 |
| --- | --- |
| `login` | 아이디, 비밀번호, 좌석 선택, 로그인 / 회원가입 버튼 |
| `using` | 좌석·이름, 남은 시간(큰 글씨), 채팅, 시간 구매 / 음식 주문 / 사용 종료 버튼 |

> 비유: 카드 묶음에서 맨 위 카드만 보이는 것처럼, `cards.show(root, "using")` 하면 사용 중 화면이 맨 위로 온다. 창을 새로 만들지 않아도 화면이 바뀐다.

## 3-3. 회원가입 (SignUpDialog)

1. 아이디, 비밀번호, 이름이 비었는지 확인
2. `memberDAO.existsById(id)`로 **아이디 중복 확인**
3. 괜찮으면 `memberDAO.insert(...)`로 DB에 저장

- `JDialog`에 `true`(모달)를 줘서, 회원가입 창이 떠 있는 동안 뒤의 게스트 창을 못 누르게 했다.

## 3-4. 로그인 (GuestFrame.login) — 검사를 순서대로

```java
if (seat == null)              → "빈 좌석이 없습니다."
if (admin.isLoggedIn(id))      → "이미 다른 좌석에서 사용 중인 계정입니다."
Member m = memberDAO.login(id, pw);
if (m == null)                 → "아이디 또는 비밀번호가 틀렸습니다."
if (m.isAdmin())               → "관리자 계정은 게스트로 로그인할 수 없습니다."
if (!seatDAO.startUse(seat, id)) → "이미 사용 중인 좌석입니다."
```

모두 통과하면:
1. DB에 있던 남은 시간을 가져온다
2. 사용 중 화면으로 바꾼다
3. 남은 시간이 0이면 → "시간을 구매해주세요" → 시간 구매 창. 그래도 0이면 바로 종료
4. **타이머 스레드 시작** (`new TimerThread(this).start()`) → [[4 스레드와 관리자]]

> [!question] 같은 계정 중복 로그인은 어떻게 막나요?
> 관리자 창이 모든 게스트 창 목록을 갖고 있다. `admin.isLoggedIn(id)`는 그 목록을 돌면서 같은 아이디로 로그인한 창이 있는지 확인한다.

## 3-5. 시간 구매 (buyTime)

1. `timeProductDAO.findAll()`로 요금표를 가져온다
2. `JOptionPane.showInputDialog`로 목록에서 고르게 한다 (`30분 - 500원`, `1시간 - 1,000원` …)
3. `paymentDAO.insert(...)`: **결제 내역 저장** (매출 계산에 사용)
4. `addSeconds(분 × 60)`: 남은 시간 늘리기
5. `saveRemainTime()`: 바로 DB에도 저장

## 3-6. 음식 주문 (orderFood)

1. `menuDAO.findAll()`로 메뉴 목록을 가져온다
2. 팝업에 메뉴 콤보박스 + 수량(1~10, `JSpinner`)을 보여준다
3. `menuDAO.decreaseStock(...)`: **재고가 충분할 때만** 차감. 모자라면 "재고가 부족합니다."로 끝
4. `orderDAO.insert(...)`: 주문 저장 (상태: 대기)
5. `paymentDAO.insert(...)`: 결제 내역 저장 (음식, 가격 × 수량)
6. `admin.onNewOrder(...)`: 관리자 채팅창에 `[주문] 3번 홍길동: 라면 2개` + 알림음, 주문 탭 새로고침

> [!question] 재고 확인을 먼저 하고 차감하면 안 되나요?
> "확인 → 차감"을 따로 하면, 그 사이에 다른 손님이 마지막 하나를 사갈 수 있다. 그래서 SQL 한 줄(`WHERE stock >= ?`)로 확인과 차감을 **동시에** 한다. → [[2 DB와 DAO]]

## 3-7. 종료 (endSession) — 4가지 경우 모두 여기로

| 언제 | 누가 부르나 |
| --- | --- |
| "사용 종료" 버튼 | 게스트 |
| 창 X 버튼 | `windowClosed` 이벤트 |
| 남은 시간 0초 | 타이머 스레드 → `forceLogout` |
| 관리자 "강제 종료" | 관리자 → `forceLogout` |

```java
private void endSession() {
    if (member == null) return;   // 로그인 안 했으면 할 일 없음
    timer.interrupt();            // 1. 타이머 멈춤
    saveRemainTime();             // 2. 남은 시간 DB 저장
    seatDAO.endUse(seatNo);       // 3. 좌석 비우기 (DB)
    admin.clearSeat(seatNo);      // 4. 관리자 좌석판도 빈자리로
    member = null;
    cards.show(root, LOGIN_CARD); // 5. 로그인 화면으로
}
```

**종료 방법이 4가지여도 정리 코드는 한 군데**에 있다. 그래서 어떤 방법으로 끝나도 시간이 저장되고 좌석이 비워진다.

> [!warning] 창 닫을 때만 저장하면 안 되나요?
> 프로그램이 갑자기 꺼지면(강제 종료, 오류) 창 닫기 이벤트가 안 온다. 그래서 타이머가 **1분마다 자동 저장**도 한다. 최악의 경우에도 1분 이하만 손해 본다.

---

## 시연 담당
1. 회원가입 → 같은 아이디로 한 번 더 가입 → "이미 사용 중인 아이디" 확인
2. 로그인 + 좌석 선택 → 사용 중 화면
3. 시간 구매 30분 → 시간 늘어남
4. 음식 주문 라면 2개 → 관리자 채팅창에 주문 알림
5. 다른 게스트 창에서 같은 계정으로 로그인 → "이미 사용 중인 계정" 확인
6. 창 X로 닫기 → (담당 2가 회원 관리 탭으로 저장 확인)

## 예상 질문
- **Q. 주문을 잘못하면 취소할 수 있나요?** → 게스트는 못 하고, 관리자가 주문 탭에서 취소한다. 취소하면 재고가 돌아오고 환불이 기록된다.
- **Q. 남은 시간이 0인 회원은 로그인 못 하나요?** → 로그인은 되고, 바로 시간 구매 창이 뜬다. 구매 안 하면 자동 로그아웃.
